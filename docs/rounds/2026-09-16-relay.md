# Relay — Sep 16 2026

Branch `relay`, off `master` at `e09a48d` (the reporting round). Ten commits,
one per phase, each typechecked on its own, so any phase can be reverted
alone. The proposal AJ approved is the Claude doc "Relay — the Planner
overhaul proposal" (Sep 16); this is what was built from it.

AJ's brief: the "Audit - planner dashboard" PDF — his architectural document
for a "Studio Command Center" plus iPad screenshots of the Sep 16 Planner.
The lines that set the bar:

> "extreme daily volume fluctuations and highly fragmented downtime … staff
> rely on instant messaging, causing notification fatigue. This new dashboard
> must eliminate off-clock digital alerts and act as an asynchronous 'hive
> mind' and 'second brain' for the studio."

> "Strategic Autonomy: trainers are empowered to execute daily cleaning,
> machine maintenance, and opening/closing duties during natural schedule
> gaps without requiring micro-management."

And the scope: "we are only reworking the planner dashboard … although some
of these events made on the planner should appear on the calendar."

## What the audit found

The Sep 16 Planner held the right things and was built like a form-filling
app: five composers each re-asking the same four questions, a three-step
wizard for a twenty-second thought, a Studio tab that was mostly empty-state
copy on a quiet day, stat cards that counted but never knew what time it was,
"Wipe down machines 0 of 20" standing in for the actual floor, native
dropdowns on an iPad, every detail as a modal over the list, taxonomy before
content in a note, a Team tab that read as a report, and a loop that never
visibly closed. Two things it got right and Relay keeps: lanes are lifespan
not topic, and nothing locks.

## Decisions

- **The name is Relay.** A team handing work from one leg to the next, and
  the part that passes a signal on without the sender staying on the line —
  the no-pings rule in one word. Verbs well: *Relay it*, *Handed to you*.
  The view id stays `studio-tasks` (bells link to it) and the folder stays
  `features/planner` (thirty imports point at it); Relay's own pieces live in
  `features/relay/relay/`.
- **Five tabs:** Floor · Mine · Notes · Team (leaders of this studio) ·
  Network (franchise and super roles), gated by `relay/RoleGate.tsx`.
- **The Now Bar is the only part that knows the time.** It reads the schedule
  rows AppContent already loads and ticks once a minute; the gap before the
  trainer's next session is what Next up, the empty prompts and the duration
  badges key off. Shift hours are per studio (`studios/{s}.shiftHours`, set
  under Team → The studio's day), defaulting to 5:30 / 10:00 / 16:00 / 20:00.
- **One composer.** Capture asks for the sentence first and the destination
  second. What it writes follows the rules, not the other way round: only
  leaders create studio templates and team jobs, any trainer posts a request
  — so a trainer's Floor capture is an ask and their Someone capture is a
  hand-off (a request carrying `forId`, ringing one bell), while a leader is
  also offered Studio task and Team job. The standing-task wizard survives
  for edits and for Team → Standards.
- **Machine wear is client-side and today-only** (option 1 of the proposal):
  sessions today with the machine in `sessionMachineIds`, counted since the
  last wipe. No Cloud Function on the log write path.
- **A wipe or deep clean is also appended to `upkeepLog`**, the log
  Operations → Equipment already reads, so the two screens never disagree.
- **Publishing a note is not a snapshot.** Every save republishes the copies
  (that is how sharing already worked), so there is no stale state to manage;
  the Save button says "Save & republish" when a note is published. "All MSF
  studios" fans the same copy out to every studio as a team share there, so
  the rules' two audiences are unchanged. Hand-off is a message prefix
  ("Hand-off —"), no schema change; the recipient's button reads Take it over.
  No live co-editing: ownership passes by hand-off and adoption.
- **Kudos recognise, never rank.** A map per document, a heart on the Pulse,
  a count per person on the Team tab shown to leaders and to the person.
  Studios are ranked on the Network tab; people never are. No points, no
  badges, no personal streaks, no push. The studio streak from the proposal
  was dropped: it would cost a seven-day instance read on every Floor open.
- **The vault is its own collection** (`studios/{s}/vault`) because rules
  apply to whole documents and nothing the floor may read sits beside an
  incident.

## What shipped, by commit

1. **The shell** — Relay, the Now Bar (`now-context.ts`), the Pulse
   (`pulse.ts`, a module store the Floor publishes into), the Context Panel
   (a right column ≥ 900px, a bottom sheet below), tabs and RoleGate; the
   request kinds `todo` and `handoff` with `forId` / `forName` / `dueOn` /
   `estMinutes` / `notifyOnDone` / `kudos`; `estMinutes` on templates;
   `shiftHours` on studios; the bottom-bar and settings labels.
2. **Capture** — the sheet and its pure half (`capture.ts`); My tasks, the
   board's ask box, the hub's Post a job and the Team tab's per-person job
   buttons open it with a preset when inside Relay; notification kinds
   `handoff` and `kudos`.
3. **The Floor** — Next up (`next-up.ts`: handed to you, due, fits the gap,
   nobody on it, touches the session you just had; at most three; Not me
   snoozes for the shift phase on this iPad), the shift rings (`rings.ts`,
   Opening = am, Mid = any, Closing = pm), `SwipeRow` (right = done, left =
   not me, long-press = quick menu), empty prompts sized to the gap, the
   Pulse published from the rows, jobs and asks the Floor already listens
   to. The glance band gives way inside Relay only.
4. **The Floor Map** — one tile per machine grouped by movement pattern in
   the Catalog's order (`machine-care.ts`), warming with touches since the
   last wipe, a bar for days since deep clean over `deepCleanIntervalDays`
   (default 14); the care sheet (Wiped / Deep cleaned / Flag) also ticks
   today's cleaning rows. **New collection** `studios/{s}/machineCare/{id}`.
5. **Mine** — Today, Handed to you (hand-offs closed with one tap that tells
   the sender, assignments, team jobs), Follow-ups (birthdays and FORD dates
   for the trainer's clients in 14 days, from the roster's own fields —
   `mine.ts`), Growth (the new `growth` category), Send to Floor.
6. **Notes** — two panes (the working log as a rail; Log / Note in
   portrait), Lift into the note, classify after writing
   (`suggest-kind.ts`), File it below the body, the "All MSF studios"
   audience (`team-share.ts`, fan-out), hand-off, Save & republish, and the
   one addition outside Relay: `ClientJotStrip` on the client's record (one
   `array-contains` query on the trainer's own notes, no index).
7. **Team** — Who's in today (from the schedule), Open loops (unanswered
   asks older than a day, flagged machines, overdue jobs), This month
   (`cohorts.ts`: renewals due, not seen 14+ days, birthdays, FORD dates,
   Routine B off → Route to team as a job with one part per client or an
   initiative), The studio's day (shift hours + deep-clean interval), the
   vault (`vault.ts`, **new collection** `studios/{s}/vault`).
8. **The Calendar layer** — `calendar-items.ts` derives reminders, personal
   tasks, timed studio tasks, jobs, initiatives and hand-offs for the days on
   screen; `RelayStrip` replaces the reminders strip; All / Mine.
9. **Kudos** — `kudos.ts`, the heart on the Pulse, the roll-up on the Team
   tab, the floor allowed to write `kudos` on a team job.
10. **Network** — Focus this quarter (`networks/{id}.relayFocus`, a banner on
    every Floor), Launch an initiative (fanned out to every studio), Studios
    ranked by new clients this month and loops closed this week (count
    queries; **one new index**: taskInstances `status` + `localDate`).

Then the documents and this ship script.

## Firestore changes

| Change | Where | Rule |
| --- | --- | --- |
| New collection | `studios/{s}/machineCare/{machineId}` | read: signed in; create/update: anyone who works at the studio, shape-checked, a new flag signed by the caller; delete: leaders |
| New collection | `studios/{s}/vault/{entryId}` | read/write: the studio's leaders, franchise owners, super admins |
| New index | `taskInstances` (`status` ASC, `localDate` ASC) | the Network tab's loops count |
| Field list | `teamJobs` update by the floor | `kudos` added to the allowed keys |
| Optional fields | `taskRequests`: `forId`, `forName`, `dueOn`, `estMinutes`, `notifyOnDone`, `kudos`; `taskInstances`: `kudos`; `taskTemplates`: `estMinutes`; `studios`: `shiftHours`, `deepCleanIntervalDays`; `networks`: `relayFocus`; a note's `teamShare.audience` may be `network` with `studioIds` | no rule change (none of these documents restricts keys) |
| Request kinds | `todo`, `handoff` | none (kind is a string) |
| Notification kinds | `handoff`, `kudos` | none |

Unchanged: Cloud Functions, the server, Mindbody, `noteShares` /
`sharedNotes` shapes.
