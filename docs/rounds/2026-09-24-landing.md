# The landing: thirteen fixes on top of the client codex (Sep 24 2026)

Branch `landing-sep24`. Shipped by `scripts/ship/ship-landing-sep24.ps1`. Nothing here is on `master` yet.

## The round in one place

On Sep 24 thirteen fixes were finished on their own branches, each written against `master` **before** the client codex (Notes & Profile as seven pages, `2026-09-24-client-codex.md`) existed. The landing brings all thirteen onto the codex in one branch, one merge each, so they reach the iPads together and none of them undoes the codex or is undone by it.

The order of work:

1. `landing-sep24` was cut from `client-codex` (with that day's `master` already merged in).
2. The thirteen branches were merged one at a time, the small ones first. After every merge the typecheck and the whole test suite had to be green before the next one started.
3. Where a fix stopped at the codex's edge (it fixed a screen the codex had since replaced), it was carried over to the codex's own page, with a test. Those are the **integration commits**.
4. The finished branch was reviewed as a whole, and the review's findings were fixed, one commit each.
5. `master` moved once more that evening (two dev-server commits) and was merged in.

Since then the client codex has gone live on its own: `master` on GitHub is `70aae66`, the codex's tip, and the restore tag `restore/2026-09-24-before-client-codex` is there. So this branch is now exactly master plus the landing: **58 commits**, then this document and the ship script.

**Nothing in Firestore changes.** No rules, no indexes, no Cloud Functions, no Mindbody code (checked: `git diff --name-only client-codex...landing-sep24` names none of them). Four server files change and deploy with the Render web service and its scheduled jobs; they are listed under "How it ships".

## The thirteen fixes

Each paragraph is what a trainer or a leader notices. The branch name is in brackets, and the branch's own round document, where it wrote one, has the detail.

**1. The dev preview no longer fails when port 3000 is busy** (`claude/hungry-darwin-57e694`). Nobody on the floor sees this one: it is for Claude and AJ on the PC. A second session's preview used to fail to start because the first held port 3000; the server now takes a free port. The evening's `master` merge brought the other half (the live-reload socket moves with it), without which the second preview reloaded forever on a blank screen.

**2. The Renewal Brief prints the Pulse overall as a real percentage** (`claude/wonderful-wilbur-feed03`). A client whose Pulse was 72% read "(1%)" on the printed Renewal Brief, and anyone under half read "(0%)", because the number is stored as a fraction and the Brief treated it as a percentage. It now reads "Yellow (72%)". The stored data is unchanged.

**3. The Deep Dive does not colour a Pulse area that was only part answered** (`claude/eager-shtern-b55802`). One low answer out of three used to turn "Sleep & Recovery" red in the Kaizen Deep Dive, while the Pulse screen itself showed "1/3" and no colour. An area now gets a colour only when all three statements are answered, and the sentence says "not enough answered in Sep" rather than inventing a reading.

**4. A stored wingspan shows in the Wingspan box** (`claude/elastic-margulis-5fc2d8`). The old record form never loaded wingspan, so the box was always empty, while machine fit's Setup screen sent trainers there to add it. The codex had already fixed this on Body & Pulse → Build, so the old file stayed deleted; what came across is the branch's guard, a test that fails if any box on the codex's pages shows or saves a field the form never loads.

**5. Asking for access to another studio carries your name, and a nameless request no longer crashes Team** (`claude/busy-sammet-af0cb0`). Request Access from the studio picker wrote a request with no name, so leaders saw a blank row, and two waiting at once took down My Studio → Team and Operations → Staff & Roles. The request now carries the person's name and email, the list never assumes a name exists ("Name not given"), and a leader is never offered "Approve and create the account" for someone who already has one (that would have replaced their account). A repair script for the old requests (`scripts/repair-studio-access-requests.ts`) is included; it is a dry run unless given `--commit`, and it has **not** been run.

**6. The chart-reading (Gemini) routes need a staff sign-in** (`claude/funny-kapitsa-fdde7f`). The two routes the old chart importer uses were open to anyone who found the address, with no limit, so a stranger could spend the studio's Gemini allowance. They now sit behind the same sign-in check as the Mindbody routes, with a per-person limit (two at once, sixty in fifteen minutes) and a 20 MB ceiling (was 50 MB). The importer shrinks each photo before sending it, so a normal chart still goes through.

**7. Clinical watch-outs reach all twenty machines** (`claude/clinical-watchouts-catalog-ids`). Nine of the twenty standard machines (pullover, chest fly, bicep, tricep, abs, lumbar, neck, hip abduction, hip adduction) never showed a watch-out, because the clinical list and the floor spell machine names differently. A client with degenerative disc disease sat down at the lumbar machine and nothing said so. Now the shield, the Now Bar, the Machine sheet and the routine rows all match, a studio's own machine is matched through the catalog machine it is based on, the shield's number is exactly what its sheet shows, and crimson is kept for absolute contraindications (high risk is plum).

**8. An abandoned session is asked about, never silently reopened** (`claude/blissful-napier-5af323`, `2026-09-24-stale-sessions.md`). Pressing Start the next morning used to reopen yesterday's forgotten session and file the day's sets under yesterday's date. Now the trainer is asked: "Judy has an unfinished session... Resume it, or Start a new session." The profile says an unfinished session is there and can Discard it. Nothing is closed or deleted on its own.

**9. Signing out starts the next person fresh; Switch Trainer hands the iPad over; Operations checks who you are every time** (`claude/nifty-archimedes-139384`). The next person on a shared iPad used to land where the last one had been, including on Operations. Signing out now clears the screen, the client and the mode, and keeps only the iPad's pinned studio. Switch Trainer is now a proper sign-out instead of dead-ending on "not registered as an authorized trainer", and Google always shows the account chooser. Operations refuses anyone who may not open it, however they got there.

**10. "Sessions before Journey" has a door** (`prior-history-door`). The editor for a client's FileMaker history existed but nothing opened it. The line under the Completed sessions count ("412 before Journey - FileMaker", or "Add sessions before Journey") now opens it: to edit for anyone who could save it, to read for everyone else, with who recorded it and when.

**11. Long-standing FileMaker clients stop reading as new** (`claude/prior-history-claims`, `2026-09-24-prior-history-claims.md`). During the migration a client with hundreds of FileMaker sessions could read "first time", "#3", "on a break" or "0 sessions". Every claim about a client's past now goes through one rule: it is judged against the home studio's cutover date, a gap is a break only where Journey sees every session, and "Client since" takes the earliest date that is actually proven.

**12. Leaving a screen with unsaved typing asks first** (`unsaved-changes-guard`, `2026-09-24-unsaved-changes.md`). Every way out (the bottom bar, the header, switching client, studio or trainer, the profile's tabs, My Studio's sections, the Operations and Admin tabs, closing a drawer) now asks "You have unsaved changes to Sam's profile. Leave without saving?", with Keep editing as the default. It also closed two bugs where typing could be saved onto the wrong client or the wrong studio.

**13. A booking is done when Journey logged a session** (`claude/booking-completed-by-journey`, `2026-09-24-done-means-logged.md`). Mindbody never sends bookings back as "Completed", so the Overview and the attendance watch could not tell who had trained. A booking now counts as done when a Journey session was finished for that client that studio day. The Overview's tiles, chase list and Team read it live (Done moves the moment End Session is pressed), a failed read says "missing" rather than "never logged", the trainer page's Upcoming drops past bookings, and the nightly renewals job's attendance watch reads the same rule.

## How it ships

`scripts/ship/ship-landing-sep24.ps1`, `prepare` then `golive`, run from the project folder on `landing-sep24` (Claude switches the folder to the branch; the landing worktree has to be removed first, because git will not have one branch in two folders). There is **no rules or index deploy**: go-live is the checks, then the push.

The client codex went first with its own script, which is the intended order. Had this one gone first, it would have carried the codex with it, because it contains it; both ways are safe.

**Server files that change** (they deploy with the Render web service and its scheduled jobs on the same push):

- `server.ts` and the new `server/gemini-routes.ts`: the chart-reading routes behind the sign-in (fix 6).
- `server/renewals-job.ts`: the nightly renewals job's attendance watch reads "done means logged" (fix 13). It reads the studios collection it already read; no new query or index.
- `server/cron-weekly-coach-report.ts`: a comment only. The job stays switched off.

**New data** is written only within today's rules: a studio access request's name and email (fix 5), a client's prior history through the door (fix 10). Both are fields the app already reads; nothing new is created.

**To undo the app**: `master` goes back to the tag `restore/2026-09-24-before-landing`, which `golive` makes and pushes before anything else. Nothing in Firestore needs undoing.

**After it is live**: reload every iPad, then walk Rounds 14, 15 and 16 of `docs/ops/TESTING-CHECKLIST.md` (the codex, signing out, done means logged) signed in as a Life Transformer, and try one abandoned session and one unsaved edit.
