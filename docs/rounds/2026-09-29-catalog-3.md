## Built

1. **`75c269a4` The Catalog's "Edit our floor" door** (Catalog R5's last piece). Under the floor on Learning → Catalog, and on an empty floor beside the door to All MSF, a button for someone who **leads here** (`leadsHere`, `features/relay/leads.ts` — the one app-side answer to "runs this studio"; `src/lib/who-works-here.ts` is membership and has no leader test): it opens **My Studio → Machines**, the ONE editor of a studio's floor, by remembering the section (`my-studio/section-memory.ts` `rememberMyStudioSection("machines")`) and switching the app's view to My Studio (`studio-tasks`), as the Hub and Operations already do. The door is AppContent's (`LearningView` → `CatalogWikiView` `onOpenFloorEditor`) and goes through Learning's leave question (`through`), so typing on the page is asked about first. No door for a trainer, none while something is typed in Find, and the Catalog draws no editor of its own — never a second editor. One line under the button says where it goes and what is there.
2. **`9b9a2d57` A catalog machine's change log** (the Codex's question 1, "later" on Sep 28). `machines/{id}/changes/{changeId}` = `{ at, by: { uid, name }, kind: "created" | "edited", fields: [...] }` — one document per save of the catalog editor, the DEFINITION FIELDS it wrote (the diff the editor already computes, filtered to `DEFINITION_KEYS`, in the definition's order, at most 80) and never the values, which are on the machine. `features/machine-codex/change-log.ts` is the record and its sentence ("Elrond Peredhel changed the stop rules and the starting weight." in `FIELD_LABELS`' words, so the vocabulary is Compare's); `change-log-store.ts` is the one writer, `recordMachineChange` — signed with the Auth uid and the name `who.ts` reads, called by `CatalogMachineEditor`'s save after the machine's own write, not awaited and never throwing — and the read: one `getDocs` of the subcollection with **no `orderBy` and no `where`**, so no index (the database builds none itself), sorted on the iPad. **What changed** is a fold on the machine's page (`catalog/MachineChangeLog.tsx`, in `MachineArticle` after How it's used), on the floor's page and on All MSF's page for a catalog machine, closed by default and read only when opened (as trends are). Three answers: couldn't be read; "No changes recorded. The log began on Sep 29, 2026; earlier corrections aren't in it." (never "never changed"); the list, newest first, a write still on its way first of all. A studio's own machine has no standard, so no log. **Rules** (`firestore.rules`, `CATALOG WAVE 3`): read signed in; create administrators only, with the shape pinned (`at == request.time`, `by.uid == request.auth.uid`, a name of 1–120, `kind` one of two, `fields` a list of at most 80, nothing else); update and delete refused for everyone. Four tests in `describe("catalog wave 3: a machine's change log")` at the end of `tests/firestore.rules.test.ts` — **not run here** (one emulator port; the integrator runs `npm run test:rules`).

## Not built: R6, head office's view, and R7, pointing Admins → Standard at it

The two round documents say, in full: "R6, head office's view on All MSF (gaps, offers, where studios changed the standard, v2 sources)" and "R7 / item 8, pointing Admins → Standard at the Catalog (needs R6 first)", plus the first round's note that R6 is "where the 'on 3 floors' count may live for head office only" (question 6). Every one of those four things already has a home on the Admins dashboard since the Admins room: gaps are `completeness()` on Admins → Standard → Machines' rows, offers are Admins → Standard → Waiting for review, where studios changed the standard is Compare on a machine, and v2 sources are the editor's Sources section with `sourceCoverage`. Building "head office's view on All MSF" from one line would have meant either drawing those four again inside Learning → Catalog (a second reading of the standard, and one tap from a second editor) or moving them (which changes `src/features/admins/AdminsDashboardView.tsx`, the integrator's file). Neither is safe to do unasked, so here is what I would build, for AJ to say yes or no to.

**R6 as I would build it — head office's view is a LAYER on All MSF, not a second screen.** For an administrator on Learning → Catalog → All MSF machines, each catalog machine's row and page carry head office's lines, read from documents the Catalog already has or reads cheaply, and every line is a sentence with a door to the Admins screen that acts on it:

- On the row: **what it is still missing**, from `completeness()` (`describeGaps`, at most two: "Missing: the dials' defaults, sources"), and **how many floors have it** — the count trainers don't see (AJ: "trainers dont need to know that"; question 8), for administrators only, from the `roster` `basedOn` collection-group read Compare already makes (one read per machine page, never on the index; on the index only after AJ says the read is worth it).
- On the page, one card, **Head office**: the gaps in full; **"3 studios changed it"** with the removed safety lines' count and a door to Compare; **"1 offer waiting"** when a pending `catalogSubmissions` entry is based on this machine, with a door to Waiting for review; **the sources** in one sentence (`coverageSentence`: "14 of 20 method lines sourced, 2 unsourced"); and the change log's last entry. The doors open the Admins dashboard at that machine (the Admins shell's `focus.machineId`, which search already uses) — that is the only new wiring, an `onOpenAdminsMachine(id)` from AppContent, through the leave question.
- Nothing on it is a score; a read that fails says "Couldn't check" on that line and the others stand.

**R7 as I would build it — Admins → Standard → Machines stays the editor; the Catalog becomes where head office READS.** "Retiring the old doors" means: the Admins machines page's rows stop drawing their own read-only summary (the gaps line, the "Where studios set their own" count) and instead say "Read it in the Catalog" with a door to Learning → Catalog → All MSF at that machine; the editor, Compare, Models and Waiting for review stay exactly where they are. So the standard has one place to be read (the Catalog, by everyone, with head office's layer on top) and one place to be written (Admins → Standard → Machines). Admins → Standard template (the standard set and the company routines) is untouched. This touches `AdminsDashboardView.tsx` (a door out to Learning) and `AppContent.tsx` (the jump into All MSF at a machine, which `learningJump` already supports), and needs no new data and no index.

**What it needs from AJ before it is built:** (1) yes to the floors count for administrators on the page (one collection-group read per page open); (2) whether the row on All MSF may carry the gaps line for administrators (the floor's rows are trainers' and stay as they are); (3) whether Admins → Standard → Machines' rows should lose their own summary lines (R7) or keep them beside the door.
