## The studio settings (the integrator's two commits)

**1 — The settings core** (`b8b83a4`, `src/features/studio-settings/`). Three layers, and the first that holds a usable value wins:

| Layer | Where | Who writes it |
| --- | --- | --- |
| This studio's own | `studios/{s}/config/settings` → `values` | the studio's leaders (the renewal settings' rule, `renewalsManageable`) |
| Max Strength's default | `system/studioDefaults` → `values` | administrators (`isSuperAdmin`) |
| The app's default | `registry.ts` | the code |

- `registry.ts` is the list: nine settings in three groups — **Relay** (a quiet floor, 2 sessions or fewer), **Where a client is** (Drifting at 2× her usual gap but never under 7 days, Lapsed after 45 days, New up to session 10, Settling in up to session 24), **The machines' care** (a deep clean every 14 days, a wipe after 4 sessions, a weekly maintenance day, none by default). Each names its reader, because every number has one.
- `resolve.ts` is the one answer to "what is this studio's value, and where did it come from". A value that isn't usable (the wrong type, out of range, a fraction where a whole number belongs, Settling in not past New) is skipped, never bent into one nobody chose, and the next layer answers. A read that failed falls through the same way, carrying `failed` so an editor can say it couldn't check.
- `store.ts` is the only writer of either document: only what changed, a cleared key deleted, signed with the Auth uid. `useStudioSettings(studioId, studioDoc)` gives a screen `value`, `source`, `loading` and `failed`; until the layers answer every value is the app's default, so no screen waits on its settings. Max Strength's defaults are one listener for the whole app, forgotten at sign-out.
- **The rules** (`firestore.rules`): `studioSettingsValid` holds the shape (`values` a map of at most 40 keys, `updatedAt`, `updatedBy` the Auth uid, nothing else); `studios/{s}/config/settings` is read by the renewal settings' readers and written by its leaders; `system/studioDefaults` is read by everyone signed in (every studio falls back to it) and written by administrators. Two rules tests ("the studio settings"); 208 in all.

**2 — My Studio → Studio → This studio's settings** (`715fb19`, `StudioSettingsPanel.tsx`). Every value with where it came from ("Now 45 days: Max Strength's default"). A studio's leaders set their own or clear a box to follow the default again; everyone else who works there reads it, locked. Only what changed is saved, each value checked first, and Settling in must end after New as entered (asked of each setting alone, because the resolver would quietly fall back to a pair that works). A layer that couldn't be read offers no save at all. **The deep clean moved here** from The studio's day: the studio's old `deepCleanIntervalDays` shows as its own, and clearing the box clears that field too, so the studio really follows the default.

Head office's editor, **Admins → Standard → Studio defaults**, is the Admins room's (below).
